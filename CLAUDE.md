# Compile & Conquer (iOS)

A coding game: you write Python-style code to control machines (a farm drone first) across
generated levels. Campaigns are per programming language; Python is first.

## Build & release rules (do not break)
- The project is generated by XcodeGen from `project.yml`; there is no checked-in `.xcodeproj`.
- CI (`.github/workflows/build.yml`) builds an unsigned IPA on every push to `main`.
- **Versions are stamped by CI only**: app version `0.1.<run_number>`, build `<run_number>`.
  Never hardcode a version in `project.yml` or Info.plist; CI verifies the IPA's version and fails otherwise.
- Release tag is `v<version>` and the asset is `CompileConquer-<version>.ipa`. The user's Mango Signer
  reads the version from the tag (minus the `v`) and groups apps by the IPA file name with digits removed,
  so keep both formats exactly like this.
- Bundle ID `com.mangomods.compileconquer` must never change (it would become a separate app).

## Design direction
- Difficulty ramps inside every language campaign: each one starts gentle at the Farm, and every
  world after it (Warehouse, Mars Mine, Ocean, Rail Yard, ...) and every level within a world gets
  progressively harder. Each new language restarts that ramp from the Farm; languages are not ranked.
- Every world is a different place with its own machine, mechanics, commands and setup code;
  only the language is shared. The Farm is the only drone/crops world. Planned direction:
  Warehouse (forklift bot: scan/pick/drop/sort, carry limit), Mars Mine (rover: battery, drilling,
  charging pads), Deep Ocean (sub: sonar search, oxygen), Rail Yard (switches and train timing).
- Shortcuts like reusing one soil tile are allowed on the Farm and the first few Warehouse levels.
  Later levels may close them off, but only through rules written visibly in that world's setup code.
- Stars: 3★ limit is computed per generated map by `Core/ParSolver.swift` (the straightforward
  solution's tick count), 2★ adds a buffer. The Farm should be forgiving; later worlds can use
  tighter limits (e.g. based on optimized solutions) so each world is harder than the last.
- Every level's main.py starts with a locked setup that declares every variable and defines every
  command with its real body (`Core/FarmSetup.swift`). Keep those bodies in sync with `FarmWorld`.
  Starter code and briefs point at the setup instead of naming the answer.
- Planned: a free currency (Bits) and a paid one (Cores, later), both cosmetic-only. Ideas live in
  `docs/IDEAS.md`; add new ideas there as they come up, don't build them until the user picks them.

## How a run works
- `Core/Python/` is our own Python subset (lexer, parser, tree-walking interpreter): variables,
  if/elif/else, while, for, def/return, lists, dicts, print, common builtins. No imports/classes.
- Pressing Run simulates the whole program instantly (`Core/Runtime/Simulator.swift`) against a
  copy of the world, recording a trace of ticks and prints; `GameSession` then plays it back.
- Each world installs its own builtins (commands + read-only objects like `drone`, `field`,
  `loader`, `floor`, `BAYS`) in `Simulator.swift`. They must match that world's locked setup code.
- The player's code is capped at 5000 lines; the editor measures its own content height.

## Settings & owner tools
- `App/AppSettings.swift`: code text size, starting speed, crop age tags, haptics.
- Owner tools: tap the version 7 times in Settings, enter the owner code (starts as "conquer").
  "Play any campaign" opens every built campaign/world; levels still unlock in order.

## Code layout
- `CompileConquer/Core` – pure game logic: Farm (`FarmWorld`, `FarmSetup`, `Levels`, `ParSolver`),
  `Warehouse/`, `Python/`, `Runtime/` (world state enums + simulator).
- `CompileConquer/Game` – the level screen, SpriteKit map scene, code editor.
- `CompileConquer/Menus` – title, campaign, world and level select.
- Landscape only, iOS 17+, Swift 5 mode, SwiftUI + SpriteKit, no external packages.
